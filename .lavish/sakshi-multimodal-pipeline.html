Two acquisition lanes.
One evidence-linked pipeline.

Observe only what opted-in notifications expose. Import only what the user selects through supported sharing and pickers. Preserve received bytes, then create local OCR, transcripts and reviewable findings as separate derivatives.

A media indicator is not the media. “Photo” or “Voice message” in a notification does not give Sakshi the pixels, audio, original URI, conversation history or authenticated sender identity.

Full report: research/android-multimodal-evidence-pipeline.md. A connected SM-S928B reported Android 16/API36, SM8650 and arm64. Only read-only platform properties were checked: no app/model install, evidence access or phone workload benchmark.

  • Notification grouping is not chat membership.

What changes by modality?

Images and screenshots: glyph fidelity, metadata and redaction

Read orientation once, retain immutable bytes and map every crop/tile back to the image. Bound decoded pixel allocations. ML Kit recommends sufficient glyph pixels, ideally 16×16; shrinking a long screenshot to one thumbnail can destroy text.

EXIF/GPS/date may be absent, edited or stripped by a source app. Preserve relevant claims privately, omit sensitive metadata from export by default. Quoted messages, forwarded content and chat headers need human review rather than automatic speaker attribution.

Redaction: create an opaque raster derivative, not reversible blur/display overlays. Remove sensitive metadata, thumbnails and matching export text. Do not attach the private original automatically.

Audio: demux is not PCM; speaker labels are not identity

MediaExtractor produces encoded samples. MediaCodec decodes PCM; handle rate/channel/format changes, delay/padding and timestamps. Resample properly to model input, with source offset mapping.

Preserve channels, original audio and VAD-omitted ranges. Denoising is a labeled derivative and can damage quiet words/nonverbal evidence. Whisper can hallucinate text on low-quality/silent input and performs unevenly across languages.

Use “Speaker A/B” or user assertions, not authenticated identity, gender, credibility, emotion or guilt. Vosk speaker models and Whisper turn markers are separate evaluated tasks, deferred from MVP. Importing audio does not require microphone permission.

Video: sampling coverage and synchronized source time

Start with selected frames or a proposed two-second interval, capped at 30 frames for a short clip. That is a design default, not complete coverage of brief threats/text. User can select extra positions.

Retriever may return a nearby keyframe; label requested/approximate time when actual PTS is unavailable. Media3 Inspector supports asynchronous decoded extraction but has thread/lifecycle requirements. Sequential decoding can provide actual PTS at greater cost.

OCR frames and STT audio are separate branches. A silent/no-audio video does not produce a transcript. Preserve rotation/HDR transformations, variable-rate timing and track offsets. Process sequentially, not all full-resolution frames in RAM.

Documents: native text, scanned pages and safe structured parsing

API35+ PdfRenderer.Page.getTextContents() can extract embedded text. Older platforms need a verified parser or page OCR. Scanned/mixed PDFs require per-page routing; invisible or erroneous text layers can disagree with the rendering.

PdfRenderer needs a seekable FD; official docs recommend an isolated minimally privileged process for untrusted PDFs. Open one page at a time. Password/corrupt/unsupported inputs are support states, not bypass tasks.

Native ordering is not semantic reading order for every script/layout. Parse exports against real fixtures and preserve raw records/date ambiguity. Do not execute HTML, load remote attachments or silently claim Office support.

PDF redaction: overlay rectangles can leave selectable text and incremental history. Use a freshly sanitized derivative/report and verify hidden text/objects/metadata are not exported.

On-device components: choose roles, not popularity

First OCR candidate

Bundled ML Kit

Small immediately available Latin/Devanagari OCR models. No native Malayalam script. Also no blanket zero-network claim: input/output stay local, but SDK metrics/update traffic is documented.

OCR + privacy sources

Indic candidate

Tesseract 5

Native CPU/JNI with selected fast language packs. Malayalam pack exists; chat fonts, mixed scripts, page segmentation and preprocessing still need quality tests.

Do not load every language pack or assume experimental OpenCL means Android NPU support.

OCR alternative

PaddleOCR

Current official Android SDK/demo uses ONNX Runtime and OpenCV, with v6 tiny/small and v5 mobile options. Detector, dictionary and matching recognizer are a pipeline, not one generic language switch.

Older Tesla T4/Xeon timing is not a phone benchmark.

First STT candidate

whisper.cpp tiny/base

Official Android sample recommends tiny/base. Multilingual mode needs per-language testing; `.en` is explicitly English-only. CPU-first, with optional backend experiments later.

No Apple Core ML/ANE performance claim applies to Android.

Language-specific alternative

Vosk small

Offline Android path and compact per-language models. Model availability is not quality: listed Telugu small-model WER is 87.9 on Fleurs. Licenses vary per model.

Do not bundle a second ASR engine without a demonstrated need.

Optional inference

ORT / LiteRT / MediaPipe

Run compatible classifiers, OCR or embeddings with exact tokenizer/model/ops. CPU first; QNN/LiteRT NPU paths require supported graphs/builds/devices.

NNAPI is deprecated in Android15. MediaPipe audio categories are not transcripts.

Embeddings, llama.cpp and mobile vision-language models

MiniLM arm64 INT8 exports offer optional 384-D search/similarity: English L6 is about 22 MiB, multilingual L12 about 113 MiB plus tokenizer/runtime. Similarity is not harassment probability, identity or duplicate-event proof.

MediaPipe supports compatible text embedder tasks and publishes current hardware-specific benchmarks. llama.cpp has Android CPU integration and separate multimodal libmtmd support requiring compatible models/projectors; ordinary text JNI examples are not multimedia integration proof.

SmolVLM-256M is an English image+text candidate. Its publisher “under 1 GB GPU RAM” claim is not Android total RAM or evidentiary OCR accuracy. Defer generation/VLMs from the minimum demo.

Pixel arithmetic

12 MP = 45.78 MiB

One RGBA image buffer, before copies/OCR/UI. Thirty 1080p RGBA frames alone are about 237 MiB. Tile images and process frames sequentially.

PCM arithmetic

1 minute = 1.83 MiB

16 kHz mono PCM16. Float32 doubles the rate. Model working state, not PCM alone, dominates ASR memory.

Bitrate arithmetic

60 s at 10 Mbps = 75 MB

Decimal compressed payload before container overhead. Original videos can dominate storage; no silent truncation to meet analysis limits.

Proposed demo limits and UX targets, all unmeasured

Images: <=20 MiB / <=12 MP, bounded tiles. Typical warm Latin OCR goal <=2 seconds, full-app PSS goal <=512 MiB. Malayalam quality/latency must be tested separately.

Audio: <=60 seconds / <=20 MiB tested input. English fixture RTF goal <=1 on reference phone; base full-app PSS goal <=700 MiB. Not promised multilingual speed.

Video: <=60 seconds / <=100 MiB tested MP4, <=30 candidate frames. PDF: <=10 MiB, initially <=5 selected analysis pages. Progress/cancel and explicit partial coverage.

These are design envelopes and acceptance goals, not expected measured performance. Battery/CPU percentages are unknown. Thermal/backend/cold-start tests must replace targets with results.

Consent and integrity are pipeline requirements

Immutable originals, honest provenance

Hash exact received bytes. A provider may have transformed them. OCR, normalized audio, frames, user corrections, translations and redactions have separate parent links and versions.

No hash proves sender, authenticity, guilt, source send time or admissibility.

Secure random access

PDF/media APIs need seeking. A whole-file encrypted stream is not automatically seekable. Avoid decrypted persistent temp files.

Android documents MediaDataSource position reads and API26 seekable proxy FDs for on-demand decryption. Use a reviewed authenticated design and test callbacks/lifecycle. Defer analysis if not ready.

Distinct user decisions

Notification opt-in, artifact retention, local analysis, model provisioning/SDK metrics, optional narration and export destination are separate purposes.

Share selection does not authorize cloud AI, gallery scanning, automatic reports or monitoring another account.

No hidden export leakage

Sanitize metadata, thumbnails, selectable PDF text and corresponding transcripts/sidecars. Never export the unredacted original merely because a preview is redacted.

Encrypted import does not delete the user's gallery/recorder/cloud copies. Backup/D2D exclusions and key-loss limits need actual tests.

ML Kit privacy nuance: official terms confirm input/output evidence stays on-device, while metrics and model/compatibility updates may contact Google. Disclose and audit the actual build. A strict no-telemetry requirement may favor bundled open-source OCR.
Protected content, ordinary exports and View Once

No private database/cache/session/key access, secure-screen override or export-restriction workaround. Ordinary source sharing/exports can be unavailable. A passive media label cannot supply missing content.

WhatsApp officially acknowledges possible native-recorder audio for View Once. A lawful independently user-produced recording may be explicitly imported; this is not original-item access, protected-pixel capture or automated recording. The separate View Once report documents that nuance.

Benchmarks before support claims

  • Actual fixtures: selected source shares/exports, revoked/transient grants, unknown sizes, locked/muted/group notifications and ordinary versus protected content.
  • Quality: per-language OCR CER/WER and critical terms; ASR silence hallucinations, code-switching, clipping and overlapping speakers; PDF text/render mismatch; video time/coverage errors.
  • Latency: import/hash/encrypt, cold load, preprocessing, inference and review-ready output separately. ASR RTF uses original source duration, not only VAD-retained speech.
  • RAM: Java/native/decoder/bitmap/GPU allocations and process PSS high-water mark, not weight file size.
  • CPU/backend: 1/2/4-thread sweeps, actual accelerator placement/fallback, hardware media decoder and numerical parity.
  • Battery/thermal: repeated sustained runs and baseline subtraction. ODPM power rails are hardware-dependent; Pixel support is not assumed on Samsung. Battery Historian is no longer actively maintained.
  • Privacy: pre-provision models and test offline; no remote recognizer fallback, evidence upload, plaintext caches or hidden redaction leakage.
  • Resilience: disk/key/decode errors, cancellation, Android16 job quotas, 16-KB native page compatibility and resource cleanup.

No on-phone workload measurement ran here. The full report supplies a reproducible 12-step benchmark protocol and 14 acceptance criteria. A connected high-end phone is a test opportunity, not a universal support certification.

Confidence + evaluation issue

What Laya actually computes

An instruction-conditioned discriminative model. It scores caller-defined finite options, not generated prose. Its typed API prevents some parsing failures, not incorrect decisions.

English

ModernBERT-large + head. Default total 512 tokens, head budget 192. About 842.6 MB safetensors; eager FP32 parameter storage alone about 1.685 GB.

Multilingual

mmBERT-base + head. Default 1,024 total tokens, explicit 8,192 option. 256k vocabulary; 34.4 MB tokenizer. English and low-resource performance differ.

Typed-decisions

About 421M, tuned on four synthetic workflows. Its reported 0.766 accuracy is not a harassment result or a zero-shot comparison.

API traps that matter to Sakshi
  • Choice is exclusive; harassment categories overlap. Use independent behaviour labels and an insufficient-context state.
  • Noul is P(true), not credibility. Split textual harm indicators from unknown identity, capability and external facts.
  • Score is an expected ordinal index, not continuous danger probability. Normalizing to 0-1 does not change that meaning.
  • Structured schema projection picks discrete levels, and rejects nested objects, arrays and arbitrary strings.
  • Long-document max-window confidence is not calibrated document confidence.
  • Router preload can retain multiple large models. Not an appropriate phone default.
Notebook audit: split and preprocessing before adapting it

The calibration holdout is selected after cases expand to question items: questions from the same state can cross train/calibration. Preprocessing uses the base checkpoint's 512/192 budget before training writes 1,024/256. Regenerate with final budgets and split conversation/case groups first.

The loss includes full soft cross-entropy alongside RLCD. The act head receives no meaningful adaptation in that loop. Require CE-only ablation, complete resume state and final-backend calibration.

Laya deployment: Linux compatibility is not Android support

Strongest research path

ONNX + native tokenizer

Actual exporter exists. Port question assembly, marker tensors, temperatures, windows and decode into Kotlin/JNI. Full ORT Android CPU first; FP32 baseline before quantization.

Not MVP default

Embedded Python

Chaquopy exists, but modern Torch/Transformers/tokenizers need compatible Android wheels or cross-builds. Linux ARM64 wheels do not establish Bionic compatibility.

No off-the-shelf Laya path

llama.cpp / GGUF

Good native path for compatible Qwen/Gemma decoders. Laya's custom encoder and decision head need architecture/converter/runtime work, not a file rename.

LiteRT, ExecuTorch, Core ML and companion services

LiteRT/ExecuTorch are real Android runtimes, but a full Laya graph export and operator/precision/parity test is still required. Core ML is an Apple path, not Android. A same-app non-exported service can isolate a working native engine, but does not solve model packaging; loopback HTTP is not private authentication.

NNAPI is deprecated from Android 15. GPU/NPU support is graph, build, runtime and device dependent, not guaranteed by a model card.

What the local probes did and did not prove

Executed / Linux only

Compact graph contracts work

Both pinned ONNX files loaded on Intel Core Ultra 9 185H CPU with ORT 1.22.1. Eight synthetic messages returned finite, correctly shaped logits. Toxicity needs ids/mask/type IDs; emotion only ids/mask.

128-token forward p50: toxicity 6.044 ms; emotion 7.796 ms. Five warmups, 30 calls, synthetic repeated input, four threads. No controlled power/cache/affinity; not phone estimates.

Synthetic diagnostic / not accuracy benchmark

Narrow models miss context

“I will wait outside your home every night until you answer me.” received threat 0.02237 and neutral emotion 0.97498. Malayalam collapsed into five unknown tokens in the English toxicity tokenizer.

These examples motivate abstention and independent rule/user-context lanes. They do not measure recall, establish calibration or validate credibility.

Promote models only after these gates

1 / compatibility

Tokenizer + graph parity

Exact IDs, markers, normalization, budgets, offsets and label order. Python reference -> float graph -> ARM64, then separately quantized graph. Test Q=1/2/4 and Unicode/code-mix.

2 / quality

Domain and language slices

Conversation/person/source-safe splits. Rare threat recall, false positives per benign messages, PR-AUC, calibration, rejected-population and context tests. Never treat synthetic fixtures as real-world evidence.

3 / resources and privacy

Real-phone end-to-end

Midrange + mainstream + flagship. PSS/peak, cold/warm latency, prefill/decode, energy/thermal, cancellation, queue saturation, offline/traffic/log/backup audit.

Published mobile results need exact artifact identities

The Qwen community mixed-INT4 benchmark uses a 474.61 MiB / 2,048-context export, not the recommended 329 MB / 4,096-context experiment. Its reported private footprint varies from 585 MB to about 2.9 GB across device/backend rows. Small download size is not small RAM.

Gemma's 2,585 tok/s figure is prefill on a specified Samsung/GPU/export, not output generation or generic phone latency. Laya's 32.8 ms is a T4 GPU result, not Android.

Build in phases, without inflated promises

Phase 1 / medium scope

Preserve, extract, review

Text/image import, encrypted originals/hashes, short audio, narrow English signals, manual correction, timeline and explicit export. Intensity null. Laya absent.

Phase 2 / high scope

Optional context interpretation

One lazy-loaded local reasoner, bounded foreground request, evidence IDs and exact quotes validated. Human fallback on unavailable model, timeout or unresolved interpretation.

Phases 3-4 / staged

Retrieve and explain patterns

Confirmed same-case context, distinct event counts, coverage gaps, reviewed transitions and role-aware expressed-emotion trajectories. Templates before generative explanations.

Phase 5 / data-intensive

Indic and code-mixed validation

MuRIL/Indic teacher candidates, compact task student, native-speaker annotations, calibrated slices, local corrections. Support badges and abstention, not universal-language marketing.

Strongest defensible differentiation: capture-aware, evidence-linked local pattern review that shows missing context and abstains. Temporal models, ensembles and local RAG already exist. The narrower gap and user benefit remain hypotheses to validate.

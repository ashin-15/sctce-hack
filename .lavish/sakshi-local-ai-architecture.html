Sakshi / local AI architecture / 02 October 2026

A small decision core.
An optional reasoning layer.

Rules, a calibrated multilingual encoder and a temporal engine do routine work. Specialist OCR/STT preserve evidence anchors. Load one local LLM for ambiguity or user-requested explanation and summary, not for every notification.

Evidence-backed architecture, not an unmeasured performance promise. Published phone benchmarks establish candidate feasibility. Sakshi harassment accuracy, Indic code-mixed recall, battery gains and total app memory remain unmeasured.

Full 15-section research report: research/local-ai-architecture.md. Covers all model fields, 26 model variants, quantization, routing arithmetic, task mapping, source revisions and release gates. No weights downloaded or phone workload executed in this investigation.

What actually runs for an observation?

The temporal branch precedes benign stop. Repeated ordinary-looking contact may matter, but history must respect consent and retention. A missing or redacted excerpt is unknown, not benign.

Always usable

Classifier-free fallback

Manual review, extraction, timeline and template reports survive missing models, refusals, low memory and unsupported languages.

Resource policy

One heavy operation

Serialize OCR, STT and generation. Reuse one foreground session, then release it. A cascade only saves peak RAM if memory actually stops being resident.

Privacy contract

Compute routing is not retention

The user can save selected evidence even if a model says ordinary. Do not retain all benign text or reversible embeddings for future AI.

Laya: why typed output is not calibrated safety

English/typed-decision checkpoints are 421M, multilingual is 322M. Outputs are choice, score and yes/no decisions in one forward pass, not generated prose. Current repository says both shipped checkpoints are overconfident, and multilingual lacks fitted temperatures.

Official dynamic INT8 exporter reports substantial decision drift. Its "weight-only" description conflicts with dynamic activation scaling. Validate the exact graph and calibrate after export. Desktop/T4 results are not phone evidence.

Weight quantization does not quantize KV

At 2K context, batch 1, FP16 cache: Qwen2.5-1.5B estimated 56 MiB; Qwen3-1.7B 224 MiB; SmolLM2-1.7B 384 MiB. FP32 doubles those figures.

Arithmetic from ordinary GQA/MHA configs. Hybrid/sliding/shared-KV architectures need a different calculation.

Specialized mobile exports are different

Gemma 4 E2B uses mixed 2/4/8-bit weights and memory-mapped embeddings. Qwen3.5 may retain norms/recurrent tensors at higher precision. A named 2B decoder does not include every multimodal weight.

Check exact files, tensors, tokenizer, backend ops and artifact revision.

Routing can save average work. It can also lose recall.

Illustrative arithmetic, not measurements

What if only some events need an LLM?

Inputs: rules/temporal 10 ms, encoder 80 ms, Laya 500 ms on 25%, LLM 6782.29 ms. Only LLM service time is borrowed from Arm's benchmark; other costs/fractions are hypothetical. No cold-load, retrieval or queue wait.

893.23 ms

86.8% less average compute than an LLM on every event.

Fully escalated path: 7372.29 ms. Remove Laya at 10% LLM routing: 768.23 ms. A 10 s cold load per LLM call adds 1 s to the average at that route rate.

Recall loss arithmetic

A later model cannot recover discarded evidence

90.3%

97% first-gate retention × 98% second-gate retention × 95% final detection = 90.3% total recall.

Hypothetical conditional recall, not measured performance or an independence assumption.

  • High-risk, uncertainty and temporal triggers bypass benign stop.
  • Unsupported language / absent text becomes unknown.
  • Calibrate thresholds on the exact production export.
  • Manual selection always remains preservable.

Latency

Plausible average savings

Depends on route fraction, prompt length and loading. Worst-case sequential escalation can be slower.

Battery

Unquantified

Measure joules/event and idle residency. Token rate and cloud cost are not battery savings.

Scheduling dependent

Filter by case, time and reviewed association. Include adjacent events, boundary messages and coverage gaps. Semantic top-k alone cannot establish counts or absence of harm.

E5-small: 117.7M, 384-D, 512-token passages, MIT. EmbeddingGemma: 300M, 768-D reducible to 128, 2K inputs, Gemma terms. Neither has validated Sakshi retrieval recall. Ten thousand 384-D float32 vectors require 15.36 MB before index/text overhead.

Embeddings are sensitive derivatives, not anonymization. Encrypt them and invalidate them on deletion/correction.

What must be measured before calling this optimal?

Quality gates

Worst-language recall

English, Malayalam, Hindi, Tamil, Telugu, Kannada, Bengali, Marathi, Hinglish, Romanized Indic and code-mixed/slang.

Conversation/source-safe splits; separate calibration set; severe-threat FN, PR-AUC, selective risk and supported-claim audit. No invented language scores.

Phone gates

Integrated app, not just CLI

Cold/warm load, 2K/4K context, p50/p95, queue wait, native/Java/driver memory, sustained thermal bursts, joules/event and idle costs.

Same phone/artifact/workload at matched recall. Exercise cancellation, OOM, screen-off and model refusal.

Architecture gates

Earn every extra stage

Encoder vs Laya; single LLM vs cascade; temporal engine on/off; lexical vs semantic history; Q4 vs Q5/Q8; specialist OCR/STT vs VLM.

Drop stages with no useful accuracy/grounding gain at their resource cost.

Concrete implementation order
  1. Supported acquisition, preserved originals, OCR/STT, source-linked manual review, timeline and templates.
  2. Fine-tune/calibrate one multilingual encoder; compare safe-export Laya as a replacement.
  3. Phone bake-off: Qwen3.5-2B CPU versus Gemma 4 E2B CPU/GPU, Qwen2.5-1.5B fallback.
  4. Select one production model pack by grounded task utility, worst-language recall, memory and energy.
  5. Add case-scoped retrieval or larger/VLM packs only after measured marginal benefit.
Targets, not achieved results: possible pilot goals include ≥98% severe-threat gating recall with confidence bounds, ≤300 ms p95 warm triage and ≤10 s short foreground review. Actual model choice and thresholds follow testing. No benchmark was run on personal notifications or selected evidence here.
